# pir-expo.alephtrade.com — инструкция для IT

Одностраничный сайт-приглашение на стенд Алеф Трейд на выставке ПИР Экспо
(26–29 октября 2026, стенд 1D50). Ниже — всё, что нужно, чтобы выложить его и обновлять.
Контекста проекта знать не нужно. Вопросы — контакт в конце.

## 1. Что это

- **Обычная статика:** HTML, CSS, JS, картинки, шрифты. Никакой сборки, фреймворков,
  PHP, базы данных и Node — файлы отдаются как есть.
- Всё содержимое сайта лежит в папке **`public_html/`** — она и есть корень сайта.
- Форм на сайте нет. Единственный внешний сервис — счётчик Яндекс.Метрики, он подключён
  из самой страницы, на сервере для него ничего не нужно.
- Боевой адрес — **`https://pir-expo.alephtrade.com`**. Сайт собран под него: канонический
  адрес, `sitemap.xml`, `robots.txt` и превью ссылки в мессенджерах указывают на него.

## 2. Первая установка

Клонировать в домашний каталог — папка `public_html` ляжет сразу как корень сайта:

```bash
git clone https://github.com/rustymetalklp-collab/pir-expo.alephtrade.com.git
```

```
pir-expo.alephtrade.com/
├── public_html/     ← корень сайта: index.html, 404.html, .htaccess, _next/, картинки
└── README.md        ← этот файл
```

Если папка домена уже существует и клонировать поверх неё нельзя:

```bash
cd ~/pir-expo.alephtrade.com
git init && git remote add origin https://github.com/rustymetalklp-collab/pir-expo.alephtrade.com.git
git fetch origin && git checkout -f -b main origin/main
```

Корень домена в панели хостинга — на `public_html` внутри клона.

## 3. Обновление сайта

```bash
cd ~/pir-expo.alephtrade.com && git pull
```

Собирать, чистить кеш и перезапускать ничего не нужно. О каждом обновлении мы пишем
отдельным письмом — репозиторий мониторить не требуется.

## 4. Что лежит в `public_html/.htaccess`

Файл для Apache на виртуальном хостинге; все блоки обёрнуты в `<IfModule>`, поэтому
отсутствие модуля не даёт ошибки 500.

- редирект `http → https` и `www → без www`;
- `ErrorDocument 404 /404.html` — своя страница «Такой страницы нет»;
- кеш: HTML и служебные файлы — `no-cache` (перепроверка по ETag), картинки, шрифты,
  CSS и JS под `/_next/static/` — год: их имена содержат хеш содержимого и меняются
  вместе с файлом;
- сжатие `deflate` для текстовых типов, MIME-типы для `webp`, `avif`, `woff2`.

Если перед Apache стоит nginx и картинки он отдаёт сам со своим кешем — это нормально,
имена файлов с хешем гарантируют, что обновления долетят.

## 5. Проверка после выкладки

1. `https://pir-expo.alephtrade.com` открывается по https, без предупреждений о сертификате.
2. `http://pir-expo.alephtrade.com` и `https://www.pir-expo.alephtrade.com` переадресуют
   на адрес из п. 1.
3. `https://pir-expo.alephtrade.com/robots.txt` отвечает `Allow: /`.
4. `https://pir-expo.alephtrade.com/нет-такой-страницы` показывает страницу 404 сайта
   (тёмная, «Такой страницы нет»), а не стандартную страницу сервера.
5. Ссылка на сайт, отправленная в Telegram, показывает карточку с картинкой и заголовком.
